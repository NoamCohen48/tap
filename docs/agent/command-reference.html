tap-agent commands

Every command of tap-agent, the CLI and MCP server an AI agent uses to drive an Android device through the Tap server. Each one lists its options, the MCP tool that does the same, and what it prints.

Experimental: commands and output may change in any release. Generated from the CLI parser for Tap 0.3.0; tap-agent <command> --help prints the same options.

Targets

A ref from the latest snapshot, such as @e3, or key=value terms joined by commas, all of which must match: id=pay, text=Pay, text~=Pay (contains), desc=, hint=, class=, pkg=, index=1.

An action needs exactly one matching node. With none or several it is refused before anything is sent to the device.

Options on every step

-s NAME picks the session (default $TAP_AGENT_SESSION, else agent). -d SERIAL picks the device when the session holds several.

Steps that act also take --settle (wait for the screen to stop changing and print what changed), --events KINDS (print the device events seen during the step), --expect KIND[:TEXT] (require one, such as toast:saved), --event-timeout and --expect-death (the step must crash a watched app).

Exit codes
  • 0done
  • 1the step failed; the reason is on stderr
  • 2the command line is wrong
  • 3no Tap server is running (tap start)
  • 4a watched app crashed or stopped responding during the step

Sessions and devices

A session is a held connection on the server: it outlives each CLI call, is shared by the CLI and the MCP server, and ends on release or after 15 idle minutes. --session NAME (or TAP_AGENT_SESSION) keeps several apart. A device is held by one session at a time, exactly as a test holds it.

Reading the screen

snapshot is the main way to see the screen: text, one node per line, grouped by window, each with a ref (@e12) to act on. A ref names a selector the server found to match exactly that node, and keeps naming it while it stays on screen. Prefer it to screenshot, which an agent has to look at. elements reads a collection, one line per match, in one bulk call, without a diagnostic snapshot; --texts projects raw text. Snapshots and settle append unread historical toasts; toast reads retained toasts without consuming them, and toast --wait waits for one. Gaps/resets are explicit; history is not current UI.

tap-agent snapshot #

Print the screen, one node per line with its ref.

tap-agent snapshot [-i | --all] [--json] [--package PACKAGE] [--window WINDOW]
    [--keyboard {collapse,show,omit}] [--system-bars {collapse,show,omit}]
-i, --interactiveinteractive controls with descendant context and labeled groups
--allevery node, layout containers too
--jsonthe complete structured snapshot with selector candidates; no view level or filter
--package PACKAGEonly windows rooted in this package
--window WINDOWonly this one-based window ordinal from the snapshot header
--keyboard KEYBOARDthe keyboard window: one header line with a count (collapse, the default), its nodes (show), or nothing (omit); one of collapse, show, omit
--system-bars SYSTEM_BARSthe status and navigation bars, as --keyboard; the shade and system dialogs always show; one of collapse, show, omit; default collapse

MCP: snapshot(view, as_json, package, window, keyboard, system_bars, device)

Examples

  • accepts= says what the node takes: tap, long, check, edit, scroll, or actions for accessibility actions only (see action).
  • The keyboard and the status and navigation bars collapse to one header line each; --keyboard show and --system-bars show list their nodes, omit drops them, and --window N shows one window in full.

Acting on elements

Every action takes a target and needs exactly one matching node: zero is NOT_FOUND, several is AMBIGUOUS, and both fail before anything touches the device. A tap whose point another window covers (a dialog, the shade) fails as NOT_INTERACTABLE / OBSCURED. With --settle, the command then waits for the screen to stop changing and prints what changed, which is usually enough to pick the next step.

tap-agent tap #

Tap a node.

tap-agent tap [--long | --double | --outside-panel] [--allow-reach-below]
    [--count COUNT] [--interval INTERVAL] [--duration DURATION]
    [--timeout TIMEOUT] target
targeta ref (@e3), comma-joined selector terms, or a JSON selector (all/any, relations, flags, text modes)
--longlong-press instead
--doubledouble-tap instead
--outside-paneltap outside the dialog, menu, drawer or sheet the target is in
--allow-reach-belowwith --outside-panel: send the touch even onto the screen under a panel that lets touches through
--count COUNTtap this many times, 1..100; default 1
--interval INTERVALrelease-to-press gap for counted taps, 40ms..1s (default 100ms)
--duration DURATIONhold the finger down for this duration, 1ms..30s (implies --long)
--timeout TIMEOUTcommand budget, at most 120s; must cover the whole gesture

Also takes the options every step takes: --settle, --events, --expect, --expect-death.

MCP: tap(target, long, double, count, interval, duration, timeout, outside_panel, allow_reach_below, settle, expect_death, events, expect_events, event_timeout_seconds, device)

Examples

  • With --settle the step waits for the screen to stop changing and prints the difference: + added, - removed.
  • A refusal says what to do next, for example several nodes match; use a ref from snapshot or a narrower selector. Nothing is sent to the device.

Device events

Android reports toasts, window changes, clicks, scrolls, text edits and content changes as they happen. Supported verbs take --events KINDS to print events observed during the step and --expect KIND[:TEXT] to require one (see each verb's options; not scroll-until). Capture is finite and observations do not prove causality. watch KIND --until-first waits for the next one, and watch streams them (run it in the background to be told when something happens). Events are hints: read the screen again before acting on one.

tap-agent watch #

Print device events as they happen, one per line, until stopped (Ctrl-C), --for ends or the device is detached; or --until-first KIND.

tap-agent watch [--package PACKAGE] [--for DURATION] [--json]
    [--until-first KIND] [--text TEXT] [--timeout TIMEOUT] [KIND ...]
KINDevent kinds, each or comma lists: toast, window, content, click, scroll, text (none with --until-first)
--package PACKAGEonly this package's events (default: any app's)
--for DURATIONstop after this long (default: until stopped)
--jsonone JSON object per line
--until-first KINDwait for the first event of this kind from now on, print it and stop (exit 1 on --timeout); one of toast, window, content, click, scroll, text
--text TEXTwith --until-first: part of the event's text, any case: a toast's message, a window's title or class, a click's label, an edit's text
--timeout TIMEOUTwith --until-first: at most 120s; default 10s

MCP: watch(kinds, duration_seconds, package, until_first, text, timeout_seconds, device)
