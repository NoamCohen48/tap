# Host Session Service (`tap serve`) and the `tap.v1` API

Date: 2026-09-19

Status: implemented (`:host:service`, `contracts/api/proto/tap.proto`), device-proven on API 29 and API 34
with the Python client. This is the contract between language bindings and the host; the
device wire protocol is unchanged and documented in `protocol-contract.md`.

## 1. Purpose

Every language binding needs the host session layer — ADB control plane, driver install and
start, port forwarding, journals, machine-wide leases, orphan recovery, quarantine, the
device pool. That layer is implemented once, in Kotlin (`:host:core`), and exposed by a small
local daemon over gRPC so every client — including the Kotlin SDK/JUnit extension — is only
a generated client plus ergonomics (see `multi-language-bindings.md` for the analysis that
led here). The service is the
**proxy** variant: it also owns the `DriverClient` connections, so bindings never touch
framing, HMAC, request IDs or blobs.

## 2. Process model

```text
pytest / script  --gRPC (loopback)-->  tap serve  --ADB + TAP1-->  driver  -->  AUT
JUnit (Kotlin)   --gRPC (loopback)-->  (same service, same pool)
```

- `tap serve [--port N] [--state-dir DIR] [--adb PATH] [--serials a,b]` binds `127.0.0.1`
  only and writes `<state-dir>/service.json` = `{"port","pid","version","adb"}` atomically.
  It prints `TAP_SERVICE_READY port=N` on stdout once listening. State dir defaults to
  `TAP_STATE_DIR` or `~/.tap`; journals and leases live in `<state-dir>/sessions`, the
  same root the `host` validation executable uses, so the two respect each other's leases
  when they share the default state dir.
- `tap status`, `tap stop`, `tap version`. Like the ADB server, a started service stays up
  until `tap stop`; clients that auto-start it do not own it and may share it.
- No client authentication: client and service run as the same user on the same machine
  (loopback). Device access is still gated by the per-session driver secret, which never
  leaves the service.
- The driver APKs are embedded as resources and extracted once per build id to
  `<state-dir>/driver/<DRIVER_APK_BUILD_ID>/`; a session installs them on first use per
  serial per process unless the client passes explicit APKs or `skip_driver_install`.
- `adb` is resolved from `--adb`, `TAP_ADB`, or `PATH`. Every ADB call is serial-specific.
- Builds: `:host:service:installDist` (JVM distribution, `host/service/build/install/tap/bin/tap`)
  and `:host:service:nativeCompile` (GraalVM native image,
  `host/service/build/native/nativeCompile/tap`, ~39 MB, links only libc/libz). Reachability
  metadata lives under `host/service/src/main/resources/META-INF/native-image/` and was
  recorded with the tracing agent over the smoke flow; re-record it when a dependency that
  uses reflection is added.

## 3. API (`contracts/api/proto/tap.proto`, package `tap.v1`)

One proto file is the single source of truth; Kotlin stubs are generated at build time,
Python stubs are generated by `clients/python/scripts/gen_stubs.py` and committed.

### RunService — ownership and liveness

| RPC | Semantics |
|---|---|
| `Open(name)` → `run_id` | A run is the ownership scope for leases and sessions. |
| `Attach(run_id)` → stream `RunEvent` | Liveness. The first event acknowledges; a heartbeat event every 15 s keeps proxies from idling out. **When the client cancels or drops the stream the run is closed**: every session is closed, every lease released (log: `closed (client detached)`). A crashed test process therefore frees its devices immediately. |
| `Close(run_id)` → `{sessions_closed, devices_released}` | Explicit teardown. Clients close before dropping the stream. |
| `Info()` | Service version, host build id, protocol version, adb path, state dir, whether a driver is bundled. |

### PoolService — one machine-wide pool

| RPC | Semantics |
|---|---|
| `Inventory()` | Devices ADB currently lists in state `device` (optionally restricted by `--serials`), with facts gathered once per serial (`api_level`, `manufacturer`, `model`, `emulator`) and state `FREE`, `LEASED(run, role)`, `QUARANTINED(reason)` from the journal, or `OFFLINE`. |
| `Acquire(run_id, roles[], timeout_ms)` | **All-or-none.** Each role carries `DeviceConstraints` (`serial`, `min_api`, `max_api`, `emulator`, `model_contains`). Pinned/most-constrained roles are matched first; the call waits (queued) up to `timeout_ms`, then fails `DEADLINE_EXCEEDED`. |
| `Release(run_id, serials[])` | Empty list = everything the run holds. Sessions on a released device are closed first. |

### SessionService — driver sessions

| RPC | Semantics |
|---|---|
| `Open(run_id, serial, aut_package, …)` → `{session_id, serial, generation, device_info}` | Requires a lease on `serial` held by `run_id` (`FAILED_PRECONDITION` otherwise). Wakes the display and dismisses an insecure keyguard, installs the bundled driver if needed, starts it with retry, and returns the driver's `DEVICE_INFO`. `default_timeout_ms` is used when a `Command.timeout_ms` is 0. |
| `Execute(session_id, command)` → `CommandResult` | One protocol request. **Driver failures are data**: `ok=false` with `error_code`/`detail`/`message`. Transport loss after transmission is also data: `TRANSPORT_LOST` or, for a transmitted mutation, `INDETERMINATE`, with `detail` = the transmission state (`NOT_WRITTEN`/`WRITTEN`); nothing is ever replayed. `request_id` and `session_generation` are echoed for diagnostics. **Cancelling the gRPC call** forwards a protocol `CANCEL` to the in-flight request; the driver honours it only before the mutation gate, and the awaited response remains the definitive outcome. |
| `Screenshot(session_id, timeout_ms, write_to?)` | Verified PNG bytes (or written to `write_to` on the host, returning the path) plus `ArtifactInfo`. |
| `DriverLog(session_id)` | The instrumentation's stdout ring buffer (last 2 000 lines). |
| `Close(session_id)` → `{clean, detail?}` | `clean=false` means the device was quarantined (`detail` says why) and stays out of the pool until the journal is recovered. |

`Command`, `Selector`, `NodeSelector`, `StringMatch`, `ResourceId`, `CommandResult`,
`ElementSnapshot`, `DeviceInfo`, `SyncState`, `ArtifactInfo` and the enums `Operation`,
`ErrorCode`, `Direction`, `MatchMode`, `MatchLimit`, `TargetScope` mirror the protocol 1.0
models one-to-one. Enum values carry a prefix (`OP_`, `ERR_`, `DIR_`, `MATCH_`, `LIMIT_`,
`SCOPE_`) plus a `*_UNSPECIFIED` zero value that the service rejects (`INVALID_ARGUMENT`).
Two tests keep the mirror honest: `EnumMirrorTest` (every proto enum equals the protocol
enum, prefixed) and `GoldenRoundTripTest` (every golden request/response fixture survives a
proto round trip unchanged). A protocol change therefore touches `protocol-contract.md`, the
golden fixtures, `contracts/api/proto/tap.proto` and the committed Python stubs in the same commit.

### AppService — AUT lifecycle

`Install`, `Uninstall`, `IsInstalled`, `ForceStop`, `ClearData`, `GrantPermission`,
`Launch`, `ColdLaunch` → `ProcessIdentity{pid, start_token}`, `Process`, `IsRunning`,
`AwaitIdle(stable_for_ms)`. These delegate to the SDK `App`, so verified process identity,
launcher-activity resolution and the sync-provider idle contract are shared with Kotlin.

### Status mapping

| Condition | gRPC status |
|---|---|
| Unknown run or session | `NOT_FOUND` |
| Invalid argument (unspecified enum, bad selector, missing field) | `INVALID_ARGUMENT` |
| Acquire timeout, wait timeout inside an app operation | `DEADLINE_EXCEEDED` |
| Precondition (no lease, app lifecycle failure, driver start failure) | `FAILED_PRECONDITION` |
| Anything else | `INTERNAL` with the exception message |

Driver-level outcomes never become gRPC errors; they are `CommandResult` values.

## 4. Client expectations

A conforming client:

1. Opens a run and attaches before acquiring anything; keeps the stream open for the run's
   life; closes the run explicitly, then drops the stream.
2. Acquires before opening a session; releases after closing it.
3. Treats `ok=false` as a typed failure keyed on `error_code` (the Python client raises
   `CommandError` with `.code`, `.detail`, request id and generation in the message).
4. Never retries a mutation on `INDETERMINATE`.
5. Puts a client-side deadline on every call that is longer than the command's own timeout
   (the Python client uses `timeout + 60 s`) so a wedged service is diagnosable.

## 5. Not implemented

- No remote (non-loopback) mode and no client authentication.
- No constraint marker beyond pinned serials in the pytest plugin (`Acquire` supports the
  constraints; the plugin exposes only `tap_serials` today).
- No event stream beyond heartbeats; per-run structured events (plan §19) belong here when
  they are built.
